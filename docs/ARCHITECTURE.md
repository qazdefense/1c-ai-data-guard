# Архитектура

## Принципы

1. **Нет данных - нет утечки.** Где можно, ИИ работает с обезличенной копией (уровень 1), а не с замаскированной живой базой.
2. **Белый список, а не чёрный.** Для живой базы (уровень 2) модель видит только разрешенные объекты и поля. Свободные тексты закрыты по умолчанию.
3. **Защита снаружи модели.** Права ограничиваются в самой 1С (отдельный пользователь, только чтение), а шлюз и его секреты живут под отдельной учетной записью ОС. Всё, что модель может прочитать на диске, считается ей известным.
4. **Каждая защита проверяется тестом.** Уровень 3 доказывает, что известные значения не выходят наружу, и запускается перед включением доступа.

## Компоненты

```
dataguard/            ядро: идентификаторы, токены, поиск, проверка утечки      (готово)
1c/Обезличивание/     внешняя обработка 1С: профили kz и ru                       (дальше)
gateway/              прокси к OData MCP: белый список, подмена, запрет raw        (дальше)
canary/               тест утечки на «канарейках»                                  (дальше)
docs/                 модель угроз, инструкции, юридическая оговорка
```

### Обезличивание (уровень 1)

Форма поставки - **внешняя обработка**: копия базы одноразовая, обработку не нужно встраивать в конфигурацию, она работает с любой
конфигурацией, где есть нужные справочники. Расширение понадобится, только если захочется постоянно блокировать внешние связи рабочей
базы; для копии достаточно обработки.

Что делает обработка (профиль задает набор идентификаторов и генераторов):
- заменяет ФИО, ИИН/БИН или ИНН/КПП/ОГРН/СНИЛС, банковские счета, контактную информацию в справочниках и регистрах из карты соответствий;
- заменой, а не удалением: ссылки в документах не рвутся, одинаковое значение всегда превращается в одно и то же синтетическое;
- верная контрольная цифра у синтетических идентификаторов, чтобы 1С не ругалась при записи;
- чистит присоединенные файлы, журнал регистрации, пароли пользователей;
- отключает регламентные задания и обмены, почту, интеграции;
- порциями, с фиксацией транзакций; в конце выдает отчет «заменено / не покрыто».

### Шлюз (уровень 2)

Прокси между ИИ и OData: ответы 1С проходят через `Tokenizer`, запросы с токенами раскрываются внутри шлюза до обращения к 1С. Сырых
запросов нет; фильтр по реальному значению запрещен. Секрет токенов и пароль 1С не доступны сессии модели.

### Проверка утечки (уровень 3)

В тестовую базу заранее вносятся «канарейки» (выдуманные ИИН, ФИО, телефоны), тест прогоняет запросы через шлюз и вызывает `leak_check`.
Любая найденная канарейка - ошибка.

## Профили

| | Казахстан | Россия |
|---|---|---|
| Идентификаторы | ИИН/БИН (12 цифр, контрольная цифра), IBAN KZ, БИК (SWIFT) | ИНН (10/12), КПП, ОГРН/ОГРНИП, СНИЛС, расчетный счет |
| Телефоны | `+7 7xx`, `8 7xx` | `+7`, `8` |
| Общее | e-mail, ФИО (через словарь известных значений) | то же |
