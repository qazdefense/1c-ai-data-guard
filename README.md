# 1c-ai-data-guard

Комплект, который позволяет работать с базами 1С вместе с ИИ-агентами и не отдавать им реальные персональные данные.
Два профиля: **Казахстан** (ИИН/БИН, IBAN KZ, БИК, номера `+7`) и **Россия** (ИНН, КПП, ОГРН, СНИЛС, расчетные счета).

Главная идея: надежно не то, что данные замаскированы, а то, что реальных данных у модели нет. Поэтому два уровня.

| Уровень | Что делает | Статус |
|---|---|---|
| 1. Обезличенная копия | Обработка 1С заменяет персональные данные в копии базы синтетическими, с верными контрольными цифрами. Агент работает с копией | в разработке |
| 2. Шлюз для живых данных | Прокси между ИИ и OData 1С: белый список объектов и полей, подмена значений токенами, запрет сырых запросов | в разработке |
| 3. Проверка утечки | «Канарейки»: заведомо известные значения кладутся в тестовую базу, тест падает, если они вышли открытым текстом | в разработке |
| Ядро | Проверка и генерация идентификаторов, поиск и подмена в тексте | готово, `dataguard/` |

## Ядро (`dataguard/`)

Стандартная библиотека Python, без зависимостей.

- `checksums.py` - ИИН, БИН, IBAN, ИНН, СНИЛС, ОГРН: проверка и генерация. Проверено по публичным примерам (IBAN из реестра ISO, ИНН и ОГРН крупных банков, пример СНИЛС из описания алгоритма).
- `scanner.py` - поиск по профилю (`profile_kz()`, `profile_ru()`), детерминированные токены `[[iin:M4T2Q9XZ7K]]` (HMAC-SHA256 с секретом шлюза), словарь известных значений для ФИО и названий в свободном тексте, `leak_check` для проверки утечки.

```
py -m unittest discover -s tests
```

## Чего комплект не обещает

- Токены защищают идентификаторы и известные значения. Суммы, даты, номера документов остаются, и по ним можно опознать контрагента.
- Свободный текст без словаря (сокращения, чужие формы названий) может пройти открытым. Поэтому шлюз работает по белому списку полей.
- Это не юридическая консультация: передачу персональных данных за границу регулирует закон, уточняйте у юриста.
